# myAIEdu 코딩 표준 (전역 공통 룰)

이 프로젝트를 여는 모든 팀원(사람/AI)에게 공통 적용된다. 구조·계층 규칙은 `architecture.md`를 따르고, 이 문서는 코드 작성 방식의 공통 룰을 정의한다.

## 역할 기준
- 코드 작성과 리뷰는 myAIEdu(4050 AI 교육 서비스 MVP, FastAPI + 정적 프론트)의 수석 테크리드 관점으로 한다.
- 실무 밸런스형으로 판단한다. 과한 추상화보다 읽기 쉽고 바로 동작하는 코드를 우선한다.
- 규칙에 어긋나는 요청은 먼저 알리고 대안을 제시한다.
- 변경을 마치기 전에 테스트 전체 통과를 확인한다.

## 1. 주석 언어 (전역 룰)
- **주석은 한국어로 작성한다.** (코드 주석, docstring, JS 주석 모두 해당)
- 식별자(변수/함수/클래스명)는 기존 컨벤션대로 영어를 쓴다. 한국어로 짓지 않는다.
- 주석은 `architecture.md`의 원칙대로 "왜"가 필요한 곳에만 단다. 코드가 이미 말해주는 "무엇"은 주석으로 반복하지 않는다.
- 죽은 코드를 주석 처리해 남기지 않는다.
- 영어 주석이 있는 기존 파일은 수정하는 부분부터 한국어로 맞춘다.

```python
# 좋은 예: 이유를 한국어로 설명
# 정원 초과 판단은 동시 신청을 막기 위해 트랜잭션 안에서 수행한다.
def enroll(self, user_id: int, cohort_id: int) -> Enrollment: ...
```

## 2. Python (src/back)
- 타입 힌트 필수. `str | None` 스타일을 쓴다.
- 함수는 작게, 한 가지 책임만 가진다.
- 임포트는 `app.` 절대경로만 사용한다 (상대 임포트 금지).
- 사용자에게 보이는 한글 메시지는 서비스의 도메인 예외 메시지로만 정의한다.
- 서비스에서 `fastapi`/`HTTPException`을 import하지 않는다.

## 3. JavaScript (src/front)
- 변수/함수는 `camelCase`.
- 서버 통신은 `js/api.js`에만 둔다. 화면 로직에서 `fetch`를 직접 호출하지 않는다.
- 서버 응답이나 사용자 입력을 `innerHTML`에 넣을 때는 반드시 이스케이프한다.
- 토큰 등 민감정보를 콘솔이나 URL에 노출하지 않는다.

## 4. 네이밍
- 파일/함수/변수: `snake_case` (Python), `camelCase` (JS)
- 클래스: `PascalCase`
- 파일은 도메인별로 나눈다 (`user_*`, `course_*`, `enrollment_*`).

## 5. 보안
- 비밀번호는 bcrypt 해시만 저장하고 평문으로 로깅하지 않는다.
- 설정값/비밀값은 `core/config.py`에서 환경변수로 읽는다. 하드코딩 금지 (개발용 기본값 제외).

## 6. 의존성과 테스트
- 새 의존성은 `src/back/requirements.txt`에 추가하고 추가 이유를 커밋/PR에 남긴다.
- API 변경 시 테스트를 함께 작성한다 (정상/예외 케이스 모두).
- 실행: `cd src/back; .\.venv\Scripts\python.exe -m pytest -q`
